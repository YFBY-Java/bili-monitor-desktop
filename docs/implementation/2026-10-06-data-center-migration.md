# 数据中心查询与操作迁移（2026-10-06）

## 业务依据与实现

逐项读取原只读 `BilibiliLiveSessionQueryService.java`、`BilibiliLiveSessionQueryRepository.java` 及完整 `frontend/src/views/data/DataCenterView.vue`，迁移以下完整使用流程：

- SQLite 直接按事件时间、插入顺序倒序分页，与原时间/id 倒序对应；同一筛选条件计算完整总数。关键词仅查询昵称、消息、礼物名称，保留原 Unicode 大小写、`%`/`_` 通配符及反斜杠转义，不把粉丝牌搜索当原功能。
- 汇总、用户和洞察读取完整场次事实，不再只统计前 100,000 条。复用已有正序读取；洞察复用一次事实读取，时间界限用线性计算，避免大数组展开溢出。聚合仍为 Core 内 O(n) 读取，没有引入新分析框架；Renderer 只接收最多 100 条事件页和 500 条用户投影。
- 筛选草稿用按钮或 Enter 提交并回第一页；每页 25/50/100。UID 复用精确整数规范化，不经 Number 舍入。事件和用户各自显示加载、错误和重试。
- 新条件成功前保留当前场次最近一次成功页；失败不会换成曾查过条件的旧缓存，也不伪装空数据。成功页由 TanStack Query 管理，记录对应筛选；取消的迟到请求不发布，换场次不串数据。
- 展示已有覆盖状态、传输连接、未解析互动/付费事件和原覆盖说明；事件数量、用户礼物事件数及付费事件数补齐。无覆盖的空白指标保持不可用，不当作零。沿用现有樱花雾白 token。

生产修改集中在 `packages/core-runtime/src/bilibili-live-session-service.ts`、`packages/storage/src/control-database.ts`、`apps/desktop/src/renderer/src/BilibiliLiveWorkspace.tsx` 和样式；无契约/schema 变更、无新采集任务。
